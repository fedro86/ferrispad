Two open documents never share a tab label

Before · A file named Untitled opened next to a new tab, or a Save As to the name of another open file, left two tabs with the same label. The window title showed the same name for both.
After · Each tab's label is worked out from the current paths every time the tab bar or the title is drawn. Files that share a name show their folder at once, and a new untitled tab keeps its plain name.

T0091 found this while it renumbered untitled tabs (its backlog, item 3). The orchestrator (ferrispad-5a) added Save As to the scope and asked for a rule that holds by construction. The cost is one pass over the open documents per tab-bar rebuild or title update. Both happen only on a user action, so the editor stays at 0% CPU when idle.

  • Tab labels are no longer cached on the document. They are computed when shown (tabs::tab_labels).
  • Only files take a folder suffix. An untitled document keeps its name, which T0091 already makes unique.
  • The tab bar and the window title read the same labels.

T0112: a label per document, worked out when shown

Before · The label was a cached field. TabManager recomputed it only on open and close, so a new tab or a Save As left it stale. An untitled document also took part in the folder suffixes, with an empty one: "Untitled ()".
After · tab_labels(&documents) computes all labels from the current names and paths. Untitled documents keep their name. Files of the same name get the shortest run of parent folders that tells them apart, and always at least one folder when an untitled tab shares their name.
  • Unchanged look: the "name (folders)" form and the minimal-folders rule are as before. A group made only of files gets exactly the labels it got before; file_labels_unchanged pins that.
  • Removed: Document::disambiguated_name, Document::tab_label and disambiguate_display_names() with its three calls.
  • Tail and chunk views keep their own display names ("x (tail)").

Why compute instead of invalidate. A cache must be cleared by every code path that changes a name or a path: open, close, new tab, Save As, tail and chunk views. One missed path makes a stale label. Computing on show makes the rule hold by construction, at the cost of one pass over the open tabs per redraw.
The tests changed shape after that red run, so both halves ran red again. The first form built a TabManager (FLTK TextBuffers) in #[cfg(test)], which T0113 forbids: macOS aborts on the first Fl::lock() off the main thread. The rule is now the pure labels_for(&[(name, path)]), and the four tests call it with the same cases. The TabManager wiring is tab_label_follows_paths_and_closes, run on the main thread by tests/fltk_main_thread.rs. The reviewer (ferrispad-90) asked for a fresh red run of each half; both probes were throwaway.

End-to-end verification

A user opens a file named Untitled and a main.rs, starts a new tab, saves it as another main.rs, then closes tabs. Every tab label stays unique at each step. Run it from the branch's worktree, with a throwaway config and data directory, so the run never reads or writes your real settings and sessions.

Starting state

  1. export XDG_CONFIG_HOME=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d); D=$(mktemp -d); mkdir -p $D/notes $D/a $D/b; echo hello > $D/notes/Untitled; echo 'fn main() {}' > $D/a/main.rs; echo $D a folder path is printed; $D/b is empty.
  2. nix develop -c cargo run -- $D/notes/Untitled $D/a/main.rs two tabs, "Untitled" and "main.rs": no other tab shares their names yet.

The scenario

  1. File → New (Ctrl+T). "Untitled (notes)" | "main.rs" | "Untitled". The file's tab shows its folder at once.
  2. Type a word in the new tab, then File → Save As… and save it as main.rs in $D/b. "Untitled" | "main.rs (a)" | "main.rs (b)". The window title starts with "main.rs (b)".
  3. Click the main.rs (a) tab, then close it (Ctrl+W). "Untitled" | "main.rs". No folder is left where none is needed.
