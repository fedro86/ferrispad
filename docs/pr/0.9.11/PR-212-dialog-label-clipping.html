Dialog labels are sized from the measured font: nothing clipped, nothing overlapping

Before · Some dialog labels were cut: "Session name:" in New Session, "Skip This Version" and "Manual Update Only" in Update. With a slightly larger desktop font, Find, Go To Line, the Font picker, Key Shortcuts, the read-only viewer and the Update buttons were cut too. Two layouts overlapped: Permissions and the Plugin Manager rows.
After · Each of those labels, buttons and check boxes takes the width its text measures when the dialog is built, never less than before. The widgets after it, and the dialog, follow. Every dialog passes the layout check with no list of known defects.

T0106's layout test, which now reaches every dialog, found these defects. The orchestrator assigned the fix for 0.9.11, and the user treats clipping and overlap as blocking. The cause was frames with fixed widths that fit one font: CI's fonts measure wider (for example, "Manual Update Only" needs 151 px there and 147 here). So nothing was tuned to this machine. Every width is measured at build time.

  • Find/Replace, Go To Line, the Font picker, New Session, Key Shortcuts, Update, the read-only viewer, File Too Large, Plugin Settings and Community Install measure their labels (label_width / max_label_width).
  • Permissions: the content ends above its buttons, and a long plugin description is cut with "…" to the window, with the full text in a tooltip. Plugin Manager rows: the text ends left of the row buttons, with "…" if it does not fit. Both use one shared helper (fit_text).
  • Only geometry changes: no colours, fonts, frame types or wording.

T0110: labels sized from the measured font

Before · Fixed frame widths, chosen for one font. The layout test passed only because 50 defects were listed in KNOWN_LAYOUT_DEFECTS (70 with CI's fonts).
After · The list is gone, and the layout test passes for every dialog, dark and light, here and on CI.

Why measure instead of widening the constants. A constant that fits this machine's font fails on CI's, and on a user's desktop font. Each width is measured when the dialog is built, floored at its old value, and the positions and dialog sizes that depend on it follow. The Shortcuts command column is capped at 440 px, so a plugin name cannot widen the dialog without bound.
