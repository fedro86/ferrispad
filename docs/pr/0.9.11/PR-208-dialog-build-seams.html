T0106: build seams so the theme guard covers every dialog

Before · 5 dialogs under the structural test.
After · Every dialog FerrisPad draws, in dark and light, with the same pixels on screen.

The orchestrator decided (2026-11-26) that T0106 stays pixel-identical: it changes how dialogs are built, not how they look. The proof is compare.sh on four scenarios added here, against master 818970b, the master this branch was last merged with.

  • Data passed in, so the test can fake it: the shortcut dialog takes the plugins' names and menu items instead of the PluginManager; the Plugin Manager takes its installed and official lists; the others take their plain data.
  • The one reorder: make_modal(true) runs in show_* right after the build, before show(). It only sets a flag FLTK reads at show().
  • Left in show_*: the font list (filled after show()), the read-only viewer's first page (it needs the mapped file), and the Plugin Manager's Community tab (it loads from the network).

No visible change: a refactor with identical output, checked by compare.sh on every dialog reachable offline. The table and the figures below are the evidence.

A pre-existing defect, not this PR's. The permission request clips a long plugin description at its right edge, on master too. The guard misses it: the test builds the dialog with a short description. T0106 must stay pixel-identical, so it went to T0110 (ferrispad-39), which fixes the dialogs' layout. T0110 now has the red test (the dialog built with a long name and description: the description needs 440 px in a 370 px widget) and the fix (the description cut with "...", the full text as a tooltip).
Why compare.sh again. The first pixel diff (2026-11-26) ran from a hand-written Xvfb script, which the new-pr skill no longer allows. The four scenarios replace it and stay in docs/pr/scenarios/, so T0110 can compare the same dialogs before and after its fixes.

Not reachable offline: the update dialog (it needs a newer release on GitHub) and the community-install review (it fetches from GitHub). Their builders hold the moved code verbatim, apart from make_modal, and the guard builds both in each variant.
