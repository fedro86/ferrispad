T0109: readable git-status colors on the file tree

Before · each git status had one fixed color for dark themes and one for light themes, whatever the tree's background. 19 status and theme pairs on the built-in themes were below 4.5:1, down to 2.31:1.
After · the tree draws readable_git_label_rgb(name, is_dark, tree_bg). That is the same fixed color when it reads at 4.5:1. Otherwise its lightness is stepped until it does: darker on a light tree, lighter on a dark one.

The step is color::push_to_contrast, the rule T0097 and T0105 already use for the list selection and the input borders. It scales toward black on a light background, which keeps the hue. On a dark background it lightens toward white, which keeps the hue too, up to integer rounding. The tree already re-resolves its label colors on every theme change, so a custom theme gets the same rule.

  • Unchanged where readable: "modified" and "added" on the dark themes, "conflict" on the light themes and on Solarized Dark, and the theme's own text color.
  • The selected row: since T0104 it draws the same git color on a soft band, so its label changes with the others. The band itself does not change.
  • Outside the tree, nothing changes. In the compare.sh shots, the window outside the tree panel is pixel-identical (AE 0) in 15 of 16 pairs. The 16th, Inspired GitHub with a row selected, differs by 8 px in the editor's right border. That is run noise: two master runs of the same theme differ by 14 px in that area.
The defect. Fixed colors chosen for "dark" or "light" ignore the actual background. Red test: git_labels_read_on_the_tree, run against master's colors (the function's body replaced by git_label_rgb, 2026-11-28), fails with 19 pairs on the built-in themes, for example: Base16OceanLight: ignored (160, 160, 160) on (239, 241, 245) = 2.31:1, SolarizedLight: modified (190, 140, 40) on (253, 246, 227) = 2.79:1, Base16MochaDark: conflict (224, 108, 117) on (59, 50, 40) = 3.93:1, InspiredGitHub: ignored (160, 160, 160) on (255, 255, 255) = 2.61:1.
Why lightness only. The user turned down restyles on 2026-11-26, and the established look is the hues: ochre, green, red, gray. A new palette was the alternative, and it would be a restyle. Stepping the lightness keeps each color recognisably itself, and the same rule already serves the list selection and the input borders.
For your decision: the selected row. On the selected row the labels sit on T0104's soft band, which is a little darker (light themes) or lighter (dark themes) than the tree. There they read at 3.02–5.75:1 with T0109, against 1.84–5.75:1 on master. That is better everywhere, but not 4.5:1 for every status. Reaching 4.5:1 on the band too would mean darker colors on light themes, or a stronger band. The band was your choice in T0104, and this PR leaves it alone. If you want the selected row at 4.5:1 as well, that is a separate ticket.
Custom themes. On a mid-tone custom background, 4.5:1 can need a near-white or near-black label. There the hue may drift up to 12° or fade toward gray. Readability wins, as for T0104's selected row. The test sweeps T0097's 54 backgrounds and allows this only off the built-in themes.

End-to-end verification

From a fresh start with a plugin that shows a tree with every git status, switch between the built-in themes and read each name. Run it from the branch's worktree, with a throwaway config and data directory, so the run never reads or writes your real settings and sessions.

Starting state

  1. export XDG_CONFIG_HOME=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d) && mkdir -p $XDG_CONFIG_HOME/ferrispad/plugins && cp -r docs/pr/scenarios/plugins/tree-demo $XDG_CONFIG_HOME/ferrispad/plugins/ ls $XDG_CONFIG_HOME/ferrispad/plugins prints tree-demo.
  2. nix develop -c cargo run -- docs/pr/scenarios/fixtures/hello.rs FerrisPad opens hello.rs. The plugin is loaded, and the left panel "demo" shows a tree: project, modified.rs, added.rs, conflict.rs, ignored.log, plain.txt.

The scenario

  1. File → Settings…: Theme "Light", Syntax Theme (Light) "Base16 Ocean Light", Syntax Theme (Dark) "Base16 Ocean Dark", Save "modified.rs" is a dark ochre, "added.rs" green, "conflict.rs" red and "ignored.log" mid-gray. All four are easy to read, as in the first figure's right column.
  2. Click "modified.rs" the row gets master's soft band, and the name keeps its ochre.
  3. File → Settings…: Syntax Theme (Light) "Solarized Light", Save; then "Inspired GitHub" the colors follow each background and keep their hues.
  4. View → Toggle Dark Mode; then, in File → Settings…, set Syntax Theme (Dark) to Solarized Dark, Base16 Eighties Dark and Base16 Mocha Dark in turn "ignored.log" is a readable gray. "conflict.rs" is a slightly lighter red, except on Solarized Dark, where it is unchanged. "modified" and "added" look as on master.
