The start page fits any window: one column when narrow, scroll when short

Before · Narrowing the window while the start page showed cut both columns and put the centred title over them. A short window cut the bottom. The page also widened the window once when it appeared.
After · Below its two-column width the page becomes one centred column. When it is taller than the window, it scrolls with a themed scrollbar. While it shows, the window keeps a minimum size of one column and the first buttons; when a tab opens, the editor's normal minimum comes back.

A user reported the clipping with a screenshot, and the user treats clipping as a blocking layout defect. The orchestrator (ferrispad-5a) assigned it for 0.9.11. The relayout happens on resize events only (a message, no timer), so the editor stays at 0% CPU when idle.

  • A pure layout rule: one column width, two columns only when they fit with their gaps.
  • A vertical scroll around the page, styled with the theme.
  • Crossing the column threshold during a resize rebuilds the page once (StartPageRelayout).
  • A minimum window size only while the start page shows.

How the start page lays out, now

Rule · column_width(button_w): two buttons and a gap, with the button as wide as the widest measured label needs. Two columns need 2 × column + 3 gaps; below that, one column. A page too short for its content reserves the scrollbar's width before deciding.
Build · show() puts the content in a vertical Scroll, at least as tall as the page so spacers still centre it. In one column, the left block (buttons, Recent Sessions, Recent Files) sits above the right block (Wiki buttons, Changelog), and the Changelog takes its content height (changelog_h).
Resize · Within a layout the content follows the width. Crossing the threshold sends one StartPageRelayout per build, and the dispatcher rebuilds the page.
Minimum · enforce_min_window_size() sets size_range to the page minimum plus the window's chrome. hide() resets it to 1×1 when a tab opens.

T0108: a responsive start page

Before · The body was one fixed row, LEFT_W + 20 + RIGHT_W (644 px), centred. A narrower window cut both sides, and a shorter one cut the bottom.
After · At every width down to the minimum, nothing visible lies outside the window, and a vertical overflow only happens inside the scroll.

Why a message, not a timer. The resize callback cannot rebuild the page itself while FLTK is laying it out, so it sends StartPageRelayout. The dispatcher rebuilds the page as the theme path already does. A drag fires one resize per motion event, so the callback sends at most one request per build (ferrispad-a3's review): three more resizes give one request, and the test was red with that flag bypassed (10 relayout requests for one build).
A visible behaviour change. While the start page shows, the window has a minimum size, and the page no longer widens the window when it appears. The minimum follows the font metrics: one column at the measured button width, plus the title and the first button rows.
