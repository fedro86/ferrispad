The selected file in the file tree is easier to see on dark themes, and its name keeps its git color

Before · The tree's selected row was the editor background shifted by about 10 % (1.26–1.37:1 against the tree), so it was hard to see which file was selected.
After · On dark themes the selected row is a soft band of 1.5:1 against the tree, derived from the theme. On light themes it is master's band, unchanged, by the user's choice. The selected file's name keeps its git color (or the normal text color for a clean file) on both. Nothing is drawn black or white instead.

Found together with T0097. The diagnostic panel was first in scope too, but the user rejected those changes ("the tree can stay, but put the diagnostics back as before"). So T0104 is the tree only, and the diagnostic panel is identical to master. A file tree comes from a plugin, such as the official file explorer. FerrisPad draws it, so the fix is in FerrisPad.

  • The tree's selection color comes from the theme: theme::panel_selection_color, applied by style_panel_selection. On a dark theme it is the tree background lightened just enough to reach 1.5:1 (PANEL_SELECTION_CONTRAST, color::shift_to_contrast). On a light theme it is master's: the background darkened to 90 %. Dark or light is the rule the tree always used: the background's mean channel (ThemeRgb::brightness) below 128.
  • The band is not registered with the contrast hook, so contrast.rs is master's. FLTK's level-10 rule keeps every label color of the built-in themes on the band.
  • The tree's timer that re-applied label colors after a selection is gone, together with the unsafe it needed.

Your two decisions. On the first version of this page (a 3:1 band with the name in black) you chose "Colore git, banda tenue". On the zooms of the 1.5:1 band in both themes you then said: "per il selected mi sembra che scuro vada meglio dopo e il light era meglio prima". So dark themes keep the 1.5:1 band, and light themes are back to master's band, exactly. The 1.5:1 on dark themes is the implementer's pick; 1.6 and 1.7 also keep every label color. It is one constant, PANEL_SELECTION_CONTRAST, and the test's bound follows it.
The tests, red on the old rules. panel_selection_band_keeps_the_label_colors checks that on every dark test background the band is at least 1.5:1 and less than 0.1 above it, and that on the 7 built-in themes every label is drawn in its own color. It fails with master's dark band ("Base16OceanDark: row (64, 68, 78) on (43, 48, 59) = 1.36:1") and with a 3:1 band ("Base16OceanLight: modified (190, 140, 40) drawn as (0, 0, 0) on the selected row (138, 139, 142)"). light_tree_selection_is_masters_band pins master's values on the 3 built-in light themes. It fails on the previous 1.5:1 light band: "Base16OceanLight left: (197, 198, 202) right: (215, 216, 220)".
Why the band is not registered. The T0078 contrast hook swaps a label for black or white when it is under 4.5:1 on a registered background. On the tree that would turn most selected names black, which is what you rejected. FLTK's own rule at level 10, which applies to unregistered backgrounds, keeps a color unless it is within 10 L* of the band. That level was lowered to 10 for exactly this tree.
Custom themes. On mid-gray backgrounds some git colors are within 10 L* of the band, so FLTK draws them black or white. In the 54-background sweep that is 47 label/background pairs with this branch, against 43 with master's band (17 against 13 on the dark half; the light half is master's). On such a background those colors are already hard to tell apart from the tree itself.

End-to-end verification

Run the branch with the screenshot fixture plugin, which shows a tree with every git-status color, click a file, and switch themes. It uses a throwaway config and data folder. Run it from the branch's checkout.

Starting state

  1. export XDG_CONFIG_HOME=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d), then mkdir -p $XDG_CONFIG_HOME/ferrispad/plugins && cp -r docs/pr/scenarios/plugins/tree-demo $XDG_CONFIG_HOME/ferrispad/plugins/, then echo '{"plugins_enabled": true, "theme_mode": "Dark", "auto_check_updates": false, "auto_check_plugin_updates": false}' > $XDG_CONFIG_HOME/ferrispad/settings.json. no output.
  2. nix develop -c cargo run -- docs/pr/scenarios/fixtures/hello.rs a dark window; on the left a tree "demo" with project and five files: modified.rs yellow, added.rs green, conflict.rs red, ignored.log gray, plain.txt in the normal text color.

The scenario

  1. Click modified.rs in the tree. a gray band you can see at a glance; the name on it stays yellow.
  2. Click plain.txt, then conflict.rs. the band moves; plain.txt stays in the normal text color, conflict.rs stays red. No name turns black or white.
  3. File → Settings... → Theme: Light → Save, then click modified.rs. the same light-gray band as in 0.9.10; the name stays orange.
