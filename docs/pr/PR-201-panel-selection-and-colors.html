Before · The tree's selected row was the editor background shifted by about 10 % (1.26–1.37:1 against the tree), so it was hard to see which file was selected.

Found together with T0097. The diagnostic panel was first in scope too, but the user rejected those changes ("the tree can stay, but put the diagnostics back as before"). So T0104 is the tree only, and the diagnostic panel is identical to master. A file tree comes from a plugin, such as the official file explorer. FerrisPad draws it, so the fix is in FerrisPad.

  • The tree's selection color comes from the theme: theme::panel_selection_color, applied by style_panel_selection. It is the tree background lightened (dark themes) or darkened (light themes) just enough to reach 1.5:1 (PANEL_SELECTION_CONTRAST, color::shift_to_contrast).
  • The band is not registered with the contrast hook, so contrast.rs is master's. FLTK's level-10 rule keeps every label color of the built-in themes on the band.
  • The tree's timer that re-applied label colors after a selection is gone, together with the unsafe it needed.

Your decision, and one number to confirm: 1.5:1. You chose "Colore git, banda tenue" on the first version of this page (a 3:1 band with the name in black). The band strength is the implementer's pick within it. On light themes the git colors are all darker than the tree, so a stronger band always takes contrast from them. 1.5:1 is a clear step from master's 1.26–1.37:1 and keeps the most for them. Stronger bands keep the colors up to 1.7:1. At 1.8:1 FLTK starts drawing Ocean Light's and Solarized Light's ignored in black. If the dark-theme band looks too faint to you, 1.6 or 1.7 are safe alternatives: it is one constant, PANEL_SELECTION_CONTRAST.
The test, red on both old rules. panel_selection_band_keeps_the_label_colors checks that the band is in [1.5, 1.6):1 against the tree on all 61 test backgrounds (7 built-in themes + T0097's 54-background sweep), and that on the built-in themes every label is drawn in its own color. With master's band it fails on every built-in theme: "Base16OceanLight: row (215, 216, 220) on (239, 241, 245) = 1.26:1". With a 3:1 band it fails on every built-in theme too: "Base16OceanLight: modified (190, 140, 40) drawn as (0, 0, 0) on the selected row (138, 139, 142)".
Why the band is not registered. The T0078 contrast hook swaps a label for black or white when it is under 4.5:1 on a registered background. On the tree that would turn most selected names black, which is what you rejected. FLTK's own rule at level 10, which applies to unregistered backgrounds, keeps a color unless it is within 10 L* of the band. That level was lowered to 10 for exactly this tree.
Custom themes. On mid-gray backgrounds some git colors are within 10 L* of the band, so FLTK draws them black or white. In the 54-background sweep that is 50 label/background pairs at 1.5:1, against 43 with master's band. On such a background those colors are already hard to tell apart from the tree itself.

End-to-end verification

Open a project with the official file explorer, click files in the tree, and switch themes. It uses a throwaway config and data folder.

Starting state

  1. export XDG_CONFIG_HOME=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d), then nix develop -c cargo run. Install the file explorer from Plugins → Plugin Manager…, and open a file inside a git repository that has a modified file. the tree on the left lists the repository, with the modified file in its git color.

The scenario

  1. Click the modified file in the tree. a gray band you can see at a glance; the name on it keeps its git color.
  2. Settings → switch between light and dark themes (for example Base16 Ocean Light and Dark) → Save; click another row, a clean file and a colored one. in each theme the band stands out from the tree; a clean file's name is in the normal text color, a colored one in its git color. No name turns black or white.

The gates

  1. nix develop -c cargo test, clippy -D warnings, cargo fmt --check all green.
