The selected file in the file tree is clearly visible, and its name stays readable

Before · The tree's selected row was the editor background shifted by about 10 % (about 1.3:1 against the tree), so it was hard to see which file was selected. Its git-colored name could become unreadable on that band: "modified" on Ocean Light was 2.12:1.
After · The selected row is a band of at least 3:1 against the tree, the same rule as the dialog lists (T0097). Its name is drawn with at least 4.5:1: in its git color when that is readable, otherwise in black or white. The other rows keep their git colors.

Found together with T0097. The diagnostic panel was first in scope too, but the user rejected those changes ("the tree can stay, but put the diagnostics back as before"). So T0104 is the tree only, and the diagnostic panel is identical to master. A file tree comes from a plugin, such as the official file explorer. FerrisPad draws it, so the fix is in FerrisPad.

  • The tree's selection color comes from the theme: theme::panel_selection_color, applied by style_panel_selection.
  • The selected row's text follows the existing contrast rule, through contrast::register_panel_selection.
  • The tree's timer that re-applied label colors after a selection is gone, together with the unsafe it needed.

T0104: a readable selected row in the file tree

Before · Click a file in the tree and the row barely changes. On light themes, a modified file's orange name sits on a near-white band.
After · The clicked row is a clear gray band, and its name is drawn so that it reads on that band.

The screenshots come from compare.sh with docs/pr/scenarios/file-tree.sh. The scenario installs the fixture plugin tree-demo into the run's throwaway config. The plugin shows a tree whose rows carry the git-status colors (modified, added, conflict, ignored, plain). The scenario then clicks modified.rs. Left: master c3672fe. Right: this branch at b760d98. The zoomed pairs are the tree region of the same shots, at 2×.

Pending user on native Wayland (GNOME): the same band and text in your theme and font. The plugin's tree reads the same as here.

Decision for the user: black text on the selected row. A rule you set (memory "no black text, keep the old look") is that a contrast fix must not swap a known look, including a text color, without your OK. Here the selected file's name is no longer drawn in its git color. It is drawn in black (in both themes shown) whenever the git color would not read on the new band. You approved keeping the tree part of T0104, but the shots above are the first before/after of this exact look. If you want a different text color on the selected row (white on a darker band, or the git color kept with a weaker band), say so before verifying.
The defect, red first. panel_selection_stands_out_in_every_theme failed on master's code for every built-in theme: the row was 1.26–1.37:1 against the tree, and colored labels were 2.1–3.9:1 on the row. Examples: Base16OceanLight "modified" (190, 140, 40) on (215, 216, 220) is 2.12:1; InspiredGitHub's row is 1.26:1. The test passes on the 7 built-in themes and on T0097's 54-background sweep.
Why the dialogs' rule. T0097 already decided how a selected list row must look (≥ 3:1, theme-derived, never an absolute color). The tree now reuses that rule, so the two can't drift apart. The text rule (the git color if it reads, otherwise black or white) is the existing T0078 contrast hook. The tree registers its selection color with it.

End-to-end verification

Open a project with the official file explorer, click files in the tree, and switch themes. It uses a throwaway config and data folder.

Starting state

  1. export XDG_CONFIG_HOME=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d), then nix develop -c cargo run. Install the file explorer from Plugins → Plugin Manager…, and open a file inside a git repository that has a modified file. the tree on the left lists the repository, with the modified file in its git color.

The scenario

  1. Click the modified file in the tree. a clearly visible gray band; the name reads on it.
  2. Settings → switch between light and dark themes (for example Base16 Ocean Light and Dark) → Save; click another row. in each theme the band stands out, and the name on it reads. The other rows keep their colors.

The gates

  1. nix develop -c cargo test (under xvfb-run, FERRISPAD_REQUIRE_UI_TESTS=1), clippy -D warnings, cargo fmt --check all green.
