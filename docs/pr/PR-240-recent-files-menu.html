FerrisPad remembers the files you opened: File → Open Recent, and on the start page

Before · There was no list of recent files. The start page's "Recent Files" card only showed files that were still in a saved session. A file you opened and closed was gone, and with session restore off (the default) the card was empty.
After · File → Open Recent lists the last 10 files you opened or saved as, newest first, and Clear Recent empties it. The start page's Recent Files card shows the first four entries of the same list. Both survive a restart.

A user asked for it in #221 and thought FerrisPad already had it, because of the start-page card. Target: 0.9.11 (the user's decision, 2026-11-27). The list changes only when you open or save a file. Nothing watches the files in the background, so FerrisPad still uses no CPU when idle (PHILOSOPHY.md).

  • File → Open Recent, right under Open…: one item per file, with the folder added when two files share a name; then Clear Recent.
  • Clicking an entry opens it, or switches to its tab when it is already open. A file that no longer exists is reported and removed.
  • The start page's Recent Files card reads the same list. A long folder is shortened with "…" so the row fits the card.

How the list works, now

Open or Save As · Every way of opening a file goes through one function: File → Open, the command line, drag and drop, a plugin, the start page and the menu. When the open really shows the file (not cancelled, no error), the path goes to the top of the list. Save As does the same with its new path.
Store · <data_dir>/ferrispad/recent_files.json holds at most 10 absolute paths, newest first, without duplicates. It is written through a temporary file, next to the sessions, and never in settings.json.
Show · File → Open Recent is rebuilt whenever the list changes. The start page re-renders its card when it is visible.
Read · At start, a missing, empty, malformed or oversized file reads as an empty list, and every entry is checked. The very first time (no file yet), the list is seeded once from the files in the saved sessions.

Test: recent_files_row_label_fits_the_card.
Why one recording point. Recording in each way of opening a file (the dialog, the command line, drag and drop, a plugin, MCP, the start page, the menu itself) would miss the next one added. FileController::open_file is the one function they all call. It appends RememberRecent only when its own actions show a file (a tab switch or a title update, and no error). A cancelled dialog or a failed read is therefore never remembered.
Seeded once after an upgrade (my decision; the reviewer may overturn it). Without it, an existing user's card would go from "files in my sessions" to empty on the first start of 0.9.11. When recent_files.json does not exist yet, the list is filled once from the named, existing files of the saved sessions, and saved. After that, only opens and Save As change it.
State, not a setting. The list lives in the data dir next to the sessions (the ticket's decision), so it never ends up in a settings.json someone shares. Clear Recent is the privacy switch. There is no setting to turn the list off (out of scope).

End-to-end verification

Open two files, close them, find them again in File → Open Recent and on the start page, and see the list survive a restart. It uses a throwaway config and data folder, so your real list, sessions and settings are untouched. From the branch's worktree:

Starting state

  1. export XDG_CONFIG_HOME=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d); D=$(mktemp -d); echo one > $D/a.txt; echo two > $D/b.txt two small files in a temporary folder.
  2. nix develop -c cargo run the start page, with an empty Recent Files card, and File → Open Recent showing "(no recent files)" greyed out.

The scenario

  1. File → Open…, pick a.txt; then the same for b.txt. Close both tabs (Ctrl+W twice). the start page's Recent Files shows b.txt, then a.txt.
  2. File → Open Recent. b.txt, a.txt, a divider, Clear Recent.
  3. Click a.txt, then File → Open Recent → a.txt again. it opens and moves to the top. The second click switches to its tab instead of opening a second one.
  4. In a terminal, rm $D/b.txt; then File → Open Recent → b.txt. an error saying it no longer exists; the entry is gone from the submenu.
  5. Quit and run nix develop -c cargo run again with the same two variables. Open Recent still lists a.txt.
  6. File → Open Recent → Clear Recent. the submenu shows "(no recent files)", and the start page's card is empty.
