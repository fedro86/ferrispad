## Goal

The `0.9.10-rc.1` release has no Windows binaries: the `build-windows` job of
`release.yml` failed (run 45821907548). GitHub's `windows-2025-vs2026` runner
image moved from MSVC 14.51 (used for 0.9.9) to MSVC 14.52, and FLTK as
bundled by `fltk-sys` 1.5.14 no longer compiles with it:

```
fltk-sys-1.5.14\cfltk\fltk\src\..\FL/math.h(46): error C2169: 'copysign': intrinsic function, cannot be defined
```

`fltk-sys` 1.5.24 (2026-11-23) fixes it (fltk-rs/fltk-rs#1706). Nothing in
CI builds Windows before a tag, so this was only found after tagging. After
this ticket, Windows builds again, a pull request shows a broken Windows build
before any tag, and `0.9.10-rc.2` ships with every platform's binaries.

## In scope

- `.github/workflows/ci.yml`: a `windows-build` job (`windows-latest`,
  `cargo build --release --locked`) on every pull request and push to
  `master`, the same build `release.yml` runs.
- `fltk` and `fltk-sys` 1.5.14 → 1.5.24 (`Cargo.toml` minimums and
  `Cargo.lock`).
- Version `0.9.10-rc.2` in `Cargo.toml`, `Cargo.lock` and
  `scripts/build-releases.sh`, plus a `## [0.9.10-rc.2]` section in
  `CHANGELOG.md`.

## Out of scope

- Running `cargo test` on Windows in CI (only the build; tests stay on the
  Linux gates).
- The `0.9.10-rc.1` release stays as published (without Windows assets);
  `rc.2` supersedes it.
- `release.yml`'s `workflow_dispatch` trigger, which would publish a release
  named after the branch and run the FlatPark job when started on a branch.
  Follow-up candidate.

## How to test

The new `windows-build` job is pushed first, on the old `fltk-sys` 1.5.14.

   `0.9.10-rc.1`; no new stderr output.

  `.deb`), Windows (`.exe` + `.zip`), macOS (`.dmg` + raw) and the `.sig`
  files for every raw binary.
- The `flatpark` job is skipped; `/releases/latest` still returns `0.9.9`;
  ferrispad.com still offers 0.9.9.

## What was done (2026-11-26)

- **Red test.** Commit `c072988` added the `windows-build` job to `ci.yml`
  on the old `fltk-sys`. CI run 45829959792: `build (windows x64)` FAILED
  with `fltk-sys-1.5.14\cfltk\fltk\src\..\FL/math.h(46): error C2169:
  'copysign': intrinsic function, cannot be defined`; both Linux jobs
  passed.
- **Fix.** Commit `efc64fb`: `fltk` and `fltk-sys` 1.5.24 (minimums in
  `Cargo.toml` raised from `1.4`/`1.5`, since older versions no longer build
  on Windows). `cargo update -p fltk -p fltk-sys` also moved the build-time
  crates `cc` 1.11.3, `cmake` 0.1.58, `find-msvc-tools` 0.1.15, `shlex`
  2.0.1, added `minipaste` and removed `ttf-parser`. No source change was
  needed. CI run 45830453111: Windows build passed (4 min 19 s), Linux
  amd64 and arm64 gates passed.
- **Gates (local).** fmt and clippy clean; `cargo test` 658 passed, 0
  failed.
- **UI (Xvfb/X11, driven by Claude).** `ferrispad-wt/uitest-T0085/run.sh`
  runs the same tour against any binary with no window manager, so every
  window lands at the same place: main window with `sample.rs`, keyboard
  selection, Find, File menu, Settings, Manage themes…, Duplicate prompt,
  the duplicated theme, the color picker, back to the editor, Help menu,
  About; Light and Dark (26 screenshots per build). Run against the `0.9.10-rc.1`
  build (`old/`) and this branch (`new/`). Every screenshot differs only on
  glyph edges (0.4–1.0 % of pixels): FLTK 1.4's X11 text drawing puts text
  less than a pixel lower and slightly crisper. Positions, sizes, colors
  and layout are identical; nothing is clipped. stderr shows only the usual
  `XOpenIM() failed` under Xvfb, in both builds.
- **Release prep.** Version `0.9.10-rc.2` in `Cargo.toml`, `Cargo.lock`,
  `scripts/build-releases.sh`; `CHANGELOG.md` `## [0.9.10-rc.2]` (Fixed:
  Windows build; Changed: FLTK 1.5.24), with the rc.1 features summarised
  since `release.yml` publishes only this section as the release notes.

Check that text, menus, Settings, Manage themes… (with Pick…) and the file
dialog look and behave as in rc.1, light and dark. Wayland draws text
through Cairo/Pango rather than Xft, so this is the part Xvfb cannot cover.
